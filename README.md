# mreact

[React](https://react.dev/)-flavored framework inspired by [Marko](https://markojs.com/)'s compiler-first philosophy.

The codebase was largely generated by an AI agent, it may be slop. To avoid polluting npm's global package namespace, it's published as a scoped package.

## Motivations

- **Fine-grained reactivity.** Update only the DOM nodes whose dependencies actually changed, not whole component subtrees.
- **Modular runtime.** Avoid shipping client runtime for routes that do not need it. A route with no client-side signals can stay server-rendered without a client route bundle.
- **Compile-time over runtime.** When a transformation can be done once by the compiler, it should not be re-done on every render in the browser.
- **Chunk-based streaming SSR.** HTML is written into a coalescing UTF-8 buffer and flushed at shell, threshold, and out-of-order fragment boundaries. The streaming path is designed to avoid buffering the full rendered document in common cases, and to let bytes leave the server as soon as they are ready, similar to Marko's streaming model.
- **Automatic client/runtime inference.** At the route level, the router/compiler infers when a route and its app-local static relative imports need client runtime (`onClick`, `cell()`, browser APIs, ...), records inferred client references in server transform metadata, and transports that manifest to the hydration runtime without developer-authored `"use client"` markers for covered patterns.
- **Dual environment optimization.** Server and client get separately compiled, separately optimized programs from one source: HTML string/stream emission on the server, fine-grained DOM mutation on the client.

## Getting Started

Create a new app with the scaffolder:

```bash
npx @reckona/create-mreact-app my-app --template app-router --src-dir
cd my-app
pnpm install
pnpm dev
```

The generated project uses an explicit Vite config:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { mreactRouter } from "@reckona/mreact-router/vite";

export default defineConfig({
  plugins: [
    mreactRouter({
      routesDir: "src/app",
      publicDir: "public",
      allowedSourceDirs: ["src"],
    }),
  ],
});
```

The recommended application layout is:

```text
my-app/
  src/
    app/
      layout.tsx
      page.tsx
    lib/
      app-info.ts
  public/
  vite.config.ts
```

Use `src/app` for routes, layouts, loaders, metadata, server actions, and route handlers. Use `src/lib` for app-local shared code. Static files go in the root-level `public` directory and are served from `/`.

Tailwind CSS v4 is available as a template:

```bash
npx @reckona/create-mreact-app my-app --template app-router-tailwind --src-dir
```

For production output:

```bash
pnpm build
pnpm start
```

## Router example

```tsx
// src/app/page.tsx
export const metadata = {
  title: "Home",
};

export default function Page() {
  return <main>Hello from mreact</main>;
}
```

This page has no client-side signals covered by route inference, so the router can render it as server HTML without emitting a client route bundle.

```tsx
// src/app/counter/page.tsx
import { cell } from "@reckona/mreact-reactive-core";

export default function CounterPage() {
  const count = cell(0);

  return (
    <button type="button" onClick={() => count.set((value) => value + 1)}>
      Count: {count.get()}
    </button>
  );
}
```

This route uses cell() and onClick, so the router emits a client bundle and hydrates the route marker.

## Packages

| Package | Purpose |
| --- | --- |
| `@reckona/mreact` | React-like public surface |
| `@reckona/mreact-dom` | DOM/client compatibility entry points |
| `@reckona/mreact-compat` | React compatibility runtime used by the public React-like packages |
| `@reckona/mreact-scheduler` | Scheduler compatibility package |
| `@reckona/mreact-compiler` | TSX compiler for client/server targets |
| `@reckona/mreact-reactive-core` | cell, computed, effect, dependency tracking |
| `@reckona/mreact-reactive-dom` | DOM bindings such as bindText, bindList, events, props |
| `@reckona/mreact-server` | SSR string/stream helpers |
| `@reckona/mreact-router` | File-based app router and build pipeline |
| `@reckona/mreact-vite` | Standalone Vite plugin for compatibility-oriented builds |
| `@reckona/mreact-query` | Server-state cache, dehydration, client hand-off |
| `@reckona/mreact-store` | Global/client state primitives |
| `@reckona/mreact-auth` | Session and authorization helpers |
| `@reckona/mreact-forms` | Form validation and server-action integration |
| `@reckona/mreact-devtools` | Shared development event hooks used by runtime packages |
| `@reckona/mreact-test-utils` | Router/SSR testing helpers |
| `@reckona/create-mreact-app` | Project scaffolder |
| `@reckona/mreact-router-native` | Optional native route matcher package with platform-specific variants |
| `@reckona/mreact-next` | Experimental Next-oriented compiler integration |

## Status

mreact is experimental. The compiler, router, SSR, reactive DOM, server actions, query, store, auth, forms, devtools, scaffolder, native helpers, and deployment adapters are being developed together, but APIs may change.
